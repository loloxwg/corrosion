# 基于图强化学习的态势数据智能推送 —— 设计(对接 4.3.3)

> 4.3.3 原文：用 **图神经网络(GNN)+深度强化学习(DRL)** 挖掘"态势数据↔作战平台"的**适配度评分函数**，
> 在时效性与战术规则约束下，智能决策推送的**目标平台/内容/路径**，减少跨平台通信冗余与传输开销。

## 1. RL 在整个系统里的位置

前面已建好"执行层"：interest/`node_interest` 决定**谁存/收哪类数据**(placement)，corrosion 按它
做部分复制(降量) + 查询路由(4.4.2)。**当前 placement 是人工规则配置**。

→ **RL = 决策层**：学一个**适配度评分函数** `score(数据类型 d, 平台 p | 态势)`，
placement 由分数导出(每类数据放在分最高的若干平台 + 覆盖约束)。**学习层输出 placement，执行层(corrosion)照办。**
这把 4.3.3 的"评分函数 + 目标平台/内容/路径"一一落地，且**不碰一致性/记账**(RL 只在合法范围内优化)。

## 2. 问题形式化

**状态 = 态势图 G=(V,E)**：
- **节点 V = 作战平台**。特征：角色(侦察/打击/干扰 one-hot)、当前任务、数据需求 profile、负载、(位置)。
- **边 E = 平台间链路**。特征：RTT/ring、通断概率、带宽(500Kbps 约束)。
- **数据类型**：作为"平台-数据"二部图的另一类节点，或作为决策的 query。

**动作 = 适配度评分 → placement**：策略对每个 `(数据类型 d, 平台 p)` 输出分数 `score(d,p)`；
placement(d) = 分数 Top-K 平台 ∪ {d 的强制消费者}(覆盖约束)。**这就是 4.3.3 的"适配度评分函数"。**

**奖励**(模拟器算)：
```
R = − 全局传输字节            (降量,4.4.3)
    − 冗余(重复投递)
    + 关心者覆盖(该收的都收到)  (时效/正确)
    + 时效(关键数据按时可见)
    − 战术规则违反             (硬约束)
    − 查询路由开销(没放的需查)  (与 4.4.2 耦合,呼应 placement 跟访问模式走)
```

## 3. 训练架构：快速模拟器训练 + 真实 corrosion 验证(sim-to-real)

**为什么不能真集群在环训练**：RL 要几千~几万次试错，每次起真 corrosion 集群+写+测≈数十秒 → 不可行。

→ **两层**：
1. **快速模拟器(Python)**：给定 placement + 态势图，**解析/轻量离散事件**算出全局传输字节、覆盖、
   时效代理(无需真集群)，毫秒级。RL 全程对它训练。
2. **真实 corrosion 验证(harness)**：把学到的 placement 配进 `node_interest` → 跑 harness →
   核对真实传输/正确性是否与模拟器一致(sim-to-real gap)。

## 4. 模型

- **GNN 编码器**(PyTorch + PyTorch Geometric)：从态势图(节点+边特征)学平台/数据的嵌入表示。
- **DRL 策略**(PPO 起步)：基于嵌入输出 `score(d,p)`；placement 由分数+约束导出。
- 训练：策略提 placement → 模拟器给奖励 → 更新。

## 5. RL 相对规则基线的价值(要证明的)

- 规则基线(人工 interest)= 固定、按角色拍脑袋。
- RL 应在**动态/复杂态势**下胜出：链路通断变化、任务重指派、数据量分布不均、覆盖与降量的权衡——
  RL 学出的自适应 placement 比静态规则**传输更省 + 覆盖/时效不降**。
- 实验：RL vs 规则 vs 随机，在多种态势(含扰动)下比奖励/传输/覆盖。

## 6. 目录与分步

代码放 `research/rl/`(Python,独立于 Rust)。harness(`cluster_bench.py`/`sweep.py`)作真实验证侧。

1. **环境/模拟器**：态势图生成 + placement→(传输/覆盖/时效) 的快速评估 + Gym 接口。
2. **基线**：随机 placement / 规则 placement(=当前人工 interest)，给出奖励基准。
3. **GNN+DRL**：PyG 编码器 + PPO 策略，学评分函数。
4. **训练 + 对比**：RL vs 基线，多态势，画学习曲线/对比。
5. **真实验证**：学到的 placement → node_interest → harness 核对 sim-to-real。

## 7.5 Codex 评审后的修订(以此为准)

**形式化调整(4 条)**：
1. **state 补齐**：除平台/链路特征外，必须含 **workload**(写频率、表大小、查询热度)、**SLA/TTL**、
   **当前 placement**、**强制消费者集合**——否则策略无法权衡"推送成本 vs 查询回源成本"。
2. **动作收窄**：先只做 `数据类型 → Top-K 平台集合`(placement)；**路径级/内容行级 RL 暂缓**
   (会同时爆动作空间和模拟器复杂度)。
3. **硬约束而非软奖励**：覆盖率、时效(TTL/deadline)、战术规则、最低副本数 → 做 **mask + repair**
   (非法 placement 不进环境评估)。奖励分层：先判硬约束(任一失败 episode 标不可接受)，
   **可行解内**再优化 `−真实推送字节 −重复投递 −查询路由字节 −anti-entropy 补偿字节`。
   覆盖用二元门槛、时效用 deadline miss 计数(别用宽泛加分)。**这是防奖励 hacking 的核心。**
4. **训练路线**：`规则监督预训练(用当前人工 interest 当标签学评分函数) → RL(PPO/REINFORCE)微调`，
   不要 PPO 从随机起点(组合放置极不稳)。

**模型**：用**二部图 GNN 或 cross-attention**(数据-平台匹配)，不是对 (d,p) 独立打分；
Top-K 后加 **diversity/coverage repair**(避免选中链路高度相关、同失效域的冗余平台)。PyG / CPU 小规模先跑通。

**sim-to-real(关键)**：模拟器必须建模 **gossip fanout/重复投递、anti-entropy 兜底、查询路由回源、
interest 收敛延迟**；用 harness 6~42 节点实测**逐分量校准**(sent/duplicate/query bytes、收敛时间分别拟合，
不能只拟合最终降量%)。更稳的折中：**采样若干 placement/扰动场景跑 harness → 训练 cost surrogate(代理模型)**
预测真机字节/时延，RL 在"解析约束 + surrogate cost"上训练(保留毫秒级，又把 gossip 放大折进去)。

**修订后的最小里程碑(几天内、能证明 RL>规则)**：
1. Gym 小模拟器(固定拓扑 10~20 节点 / 3~5 类数据 / 毫秒级 step)。
2. 规则 baseline(=当前人工 interest)+ 随机 baseline。
3. **硬约束 repair 层**(强制消费者/最低副本/TTL)——先保证任何输出都合法。
4. **二部图 GNN scorer，用规则标签监督训练** → 输出 score heatmap，Top-K 能复现规则 baseline。
5. RL 微调(只在可行解内比字节/重复/查询开销)→ 扰动态势下优于规则、覆盖/时效不降。
6. 最优 placement 注入 `node_interest` 跑 harness → sim 与真机字节趋势对齐。

**交付证据链(技术报告必须有)**：①评分函数可视化(数据-平台 score heatmap + 态势变化前后 score 变化)；
②基线对比(规则 vs 随机 vs GNN+DRL：传输/重复/查询/覆盖/deadline miss)；③sim-to-real 对齐图；
④消融(无GNN / 规则only / GNN监督 / GNN+RL)——证明提升来自"GNN+DRL 挖到适配度"而非手工约束/Top-K 启发式。

**三大风险(按严重)**：①奖励 hacking 致少发(硬约束 mask 防)；②模拟器失真 sim-to-real(harness 校准/surrogate)；
③PPO 从零不稳(监督预训练缓解)。

## 7. 风险与开放

- **模拟器保真度**：传输模型若与真 corrosion(gossip 放大/anti-entropy)差太远，学到的策略真机不灵。
  → 模拟器要用 harness 实测数据校准(已有 6~42 节点降量曲线可作锚点)。
- **动作空间规模**：(数据类型 × 平台) 组合;先小规模(3 类数据 × ~10 平台)跑通,再放大到 100 节点。
- **约束处理**：覆盖/战术规则作硬约束(mask 非法动作)或重罚,别让 RL 学出"全不发"骗降量。
- **训练成本**：GNN+PPO 训练资源;先 CPU 小规模可行,大规模再上 GPU。
- **与合同**：交付 = 模型 + 训练/对比实验 + 技术报告;RL 不替代正确性(执行层守)。
